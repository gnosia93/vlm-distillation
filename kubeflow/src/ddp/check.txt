1. local-nvme 마운트 경로 검증 (hostPath)
•	상황: YAML의 hostPath.path에 /mnt/nvme로 지정되어 있습니다.
•	점검: EKS Node Group의 Launch Template이나 인스턴스 시작 스크립트(UserData)에서 로컬 NVMe SSD를 실제 포맷 후 어느 경로에 마운트하도록 해두었는지 확인이 필요합니다.
•	Karpenter 또는 EKS 기본 AMI 환경에 따라 /mnt/nvme, /mnt/k8s-disks/..., /tmp 등 경로가 다를 수 있습니다.
•	권장: 데이터셋이 로컬 NVMe 공간을 통째로 쓰게 할 경우 해당 경로가 읽기/쓰기 권한(Permission) 및 존재 여부가 노드 레벨에서 보장되어 있어야 합니다.

  2. ClusterTrainingRuntime 내 컨테이너 이름 확인
•	상황: runtimePatches 아래 replicatedJobs[0].name: node 및 containers[0].name: node로 작성되어 있습니다.
•	점검: 클러스터에 설치된 torch-distributed 런타임의 기본 정의에서 메인 컨테이너 이름이 node인지 확인합니다. (일부 Kubeflow Training Operator 설치본은 node 대신 trainer 또는 main으로 지정되어 있기도 합니다.)
kubectl get clustertrainingruntime torch-distributed -o yaml | grep -i "name:"



EKS 노드의 로컬 NVMe 마운트 경로를 확인하는 가장 확실하고 빠른 방법 3가지를 소개해 드립니다.
상황에 맞게 편한 방법을 선택하셔서 실행해 보세요!
방법 1. 임시 파드(Pod)를 띄워 노드 내부 직접 조회 (추천 ⭐️)
hostPath를 이용해 노드의 Root(/) 디렉터리를 그대로 읽는 임시 파드를 하나 띄운 뒤, df -h 나 lsblk 명령어로 마운트 위치를 즉시 확인하는 방법입니다.
	1.	임시 점검용 파드 생성 및 접속
kubectl run nvme-check --rm -i --tty --image=busybox --overrides='
{
  "spec": {
    "containers": [{
      "name": "checker",
      "image": "busybox",
      "command": ["sh"],
      "volumeMounts": [{
        "mountPath": "/host",
        "name": "host-root"
      }]
    }],
    "volumes": [{
      "name": "host-root",
      "hostPath": { "path": "/" }
    }]
  }
}'

	2.	파드 내부 쉘 진입 후 디스크 마운트 정보 확인
# 호스트의 마운트 정보 출력 (NVMe 관련 마운트 지점 찾기)
df -h | grep -i nvme

# 또는 /host 기준 마운트 디렉터리 직접 확인
ls -la /host/mnt/

이곳에서 /host/mnt/nvme 인지, /host/mnt/k8s-disks/... 인지 실제 노드에 마운트된 경로를 눈으로 바로 확인하실 수 있습니다.
방법 2. SSM / SSH로 EKS 노드(EC2)에 직접 접속
EKS 노드 그룹에 AWS Systems Manager(SSM) 세션 매니저 권한이 설정되어 있거나 SSH 접속이 가능하다면, 해당 노드에 직접 들어가서 확인할 수 있습니다.
# AWS CLI로 SSM 접속
aws ssm start-session --target <g7e.12xlarge-노드의-EC2-인스턴스-ID>

# 접속 후 마운트 상태 확인
df -h
# 또는 NVMe 블록 디바이스 마운트 경로 전체 확인
lsblk

방법 3. 노드 생성 시 사용된 Launch Template / User Data 확인
만약 노드 그룹을 생성할 때 Karpenter나 EKS Managed Node Group의 UserData(선행 스크립트)를 통해 NVMe를 포맷하고 마운트하도록 설정했다면, 그 스크립트 안에 경로가 적혀 있습니다.
•	EKS Node Viewer / UserData 점검:
EC2 콘솔 -> 해당 g7e.12xlarge 인스턴스 선택 -> [고급 세부 정보] -> [사용자 데이터(User Data)] 확인.
•	보통 mkfs.ext4 /dev/nvme... 및 mount /dev/nvme... /mnt/nvme 와 같은 명령어가 포함되어 있으므로, 설정된 마운트 목적지 경로를 바로 찾아낼 수 있습니다.
💡 TIP: 만약 노드에 NVMe 마운트가 아예 안 되어 있다면?
AWS EKS 기본 AMI는 인스턴스 스토리지(NVMe)를 자동으로 포맷/마운트해주지 않는 경우가 많습니다. 만약 위의 명령어를 쳤는데 아무것도 마운트되어 있지 않다면, Launch Template의 userData에 아래와 같은 포맷/마운트 스크립트가 들어가 있는지 확인해 보셔야 합니다.
# 예시: NVMe 디바이스 포맷 및 /mnt/nvme 마운트 스크립트
mkfs.ext4 /dev/nvme1n1
mkdir -p /mnt/nvme
mount /dev/nvme1n1 /mnt/nvme
