## 영상 프레임 샘플링

영상은 초당 수십 프레임(fps)이라 전부 처리하면 비용이 폭발한다. 샘플링은 "몇 장을, 어떤 기준으로 뽑을지"를 정하는 단계로, 처리량·비용·정확도를 좌우하는 가장 큰 손잡이다. 뽑은 프레임만 VLM/SAM-3에 들어가므로, 샘플링 설계가 곧 파이프라인 비용과 탐지 성능을 결정한다.

​```
영상(mp4) → [디코딩] → [샘플링] → 프레임 → VLM / SAM-3
                          ↑ 여기서 몇 장·어떤 기준으로 뽑을지 결정
​```

### 샘플링 방법

| 방법 | 원리 | 장점 | 단점 | 적합 |
|------|------|------|------|------|
| 균일(Uniform) | 고정 간격 (예: 1fps, 또는 구간당 N장 균일) | 단순·예측 가능 | 정적 구간 낭비, 순간 사건 놓칠 수 있음 | 기본 baseline |
| 키프레임(I-frame) | 코덱의 키프레임만 디코딩 | 디코딩 비용 최소 | 간격이 정확히 일정하진 않음 | 값싼 1차 훑기 |
| 모션 기반(Content-aware) | 프레임 차분 → 변화 있을 때만 추출 | 정적 배경에서 대부분 스킵 | 조명·흔들림에 오탐 | CCTV(정적 배경) |
| 적응형/계단식(Adaptive) | 평소 듬성 + 이벤트 감지 시 조밀 | 비용↓ + 순간 사건 포착 | 구현 복잡 | 실전 권장 |
| 장면전환(Shot/Scene) | 장면 바뀌는 지점 추출 | 의미 단위로 샘플 | CCTV엔 장면전환 드묾 | 편집 영상 |
| 슬라이딩 윈도우 | 겹치는 구간으로 나눠 반복 | 긴 사건이 경계에 걸려도 포착 | 중복 연산 | 긴 이벤트 |

같은 "샘플링"이라도 뒤에 어떤 모델이 오느냐에 따라 요구가 달라진다.

VLM은 한 번에 정해진 프레임 수(예: 16장)를 받는 모델이다. 따라서 하나의 시간 구간에서 N장을 균일하게 혹은 내용 기반으로 추출해 하나의 "클립"으로 투입한다. 여기에는 커버 범위와 시간 해상도 사이의 트레이드오프가 존재한다. 예를 들어 16장을 60초에 걸쳐 뿌리면 긴 사건을 담을 수 있지만 프레임 간격이 성겨지고, 반대로 16초에 몰아 뿌리면 촘촘하지만 짧은 구간만 보게 된다. 그래서 하나의 클립으로 담기 어려운 긴 사건은 슬라이딩 윈도우로 나눠 여러 클립으로 처리한다.

반면 SAM-3는 프레임을 순서대로 흘려보내며 메모리로 추적하는 모델이다. 추적의 연속성을 유지하려면 충분한 시간적 밀도가 필요한데, 샘플링이 너무 듬성하면 객체를 놓치거나 프레임 간 동일 객체의 식별이 어긋나는 ID 전환(ID switch)이 발생한다. 따라서 SAM-3는 VLM보다 더 촘촘한 샘플링을 원하는 경향이 있다.

정리하면, VLM은 고정된 N장 묶음을 입력으로 받아 구간을 대표하는 몇 장으로 요약하는 것이 관건이고, 긴 사건은 슬라이딩 윈도우로 다룬다. SAM-3는 순차 프레임 시퀀스를 입력으로 받아 추적 연속성이 관건이며, 밀도가 부족하면 추적이 끊기고, 긴 사건은 스트리밍과 메모리로 이어서 처리한다.

샘플링 레이트를 정하는 원칙은 세 가지다. 첫째, 잡으려는 사건의 시간 스케일에 맞춘다. 넘어짐 같은 순간적 사건은 초당 여러 장이 필요하고, 재실 여부나 활동 같은 지속적 상태는 몇 초에 한 장으로도 충분하다. 둘째, 배경이 정적인 CCTV라면 모션 게이팅으로 대부분의 프레임을 건너뛴다 — 이것이 비용 절감의 핵심이다. 셋째, 모델별 우선순위가 다르다는 점을 기억한다. VLM은 구간을 잘 대표하는 것을, SAM-3는 추적이 끊기지 않을 밀도를 우선한다.

### 실전 권장 (CCTV 등 정적 배경)

계단식으로 조합하는 것이 비용·정확도 모두에 유리하다.

​```
1차 (항상): I-frame 또는 1fps + 모션 차분 → 변화 없으면 스킵 (대부분 걸러짐)
2차 (움직임 감지 구간만): 초당 3~5장으로 조밀 재샘플링
3차 분기:
   - VLM  → 그 구간에서 16장 균일 추출 (클립)
   - SAM-3 → 그 구간 시퀀스를 순차 투입 (추적)
​```

- 평소 얇게, 이벤트만 조밀 → 처리 프레임 수 대폭 감소.
- I-frame 우선 디코딩으로 앞단 비용까지 절감.

### 이벤트 경계(시작/종료) 탐지

이벤트의 시작과 끝을 탐지하는 일은 무거운 모델(SAM·VLM)이 아니라 앞단의 값싼 연산이 담당한다. 즉 프레임에서 저렴하게 얻을 수 있는 신호, 주로 움직임(모션)을 임계값과 비교해 경계를 판단하는 것이 기본이다.

판단에 쓰는 신호는 크게 세 가지다. 첫째는 **프레임 차분(Frame Differencing)**으로, 연속된 프레임의 픽셀 차이를 계산해 변화량을 모션 점수로 삼는다. 변화가 크면 무언가 움직인 것이고, 변화가 없으면 정적인 상태다. 둘째는 **배경 차분(Background Subtraction, MOG2·KNN)**으로, 정적인 배경을 모델링한 뒤 그와 달라진 전경 픽셀을 움직임으로 간주한다. 전경 면적이 임계값을 넘으면 활동이 있는 것으로 보며, 배경이 고정된 CCTV에 특히 잘 맞는다. 셋째는 경량 CNN 존재 감지로, 샘플 프레임마다 "사람이 있는가"를 판별해 사람이 등장하면 시작 후보, 사라지면 종료 후보로 삼는다.

경계 판단 로직은 이 과정의 핵심이다. 단순히 "점수가 임계값을 넘으면 시작"으로 처리하면 경계 근처에서 켜졌다 꺼졌다를 반복하는 깜빡임(flicker)이 심해지기 때문에, 실무에서는 몇 가지 안전장치를 함께 쓴다. 우선 히스테리시스를 적용해 시작 임계값(높음)과 종료 임계값(낮음)을 따로 둔다. 높은 임계값을 넘으면 시작으로 보고, 낮은 임계값 아래로 내려가야 종료 후보로 보는 식으로 두 값을 벌려두면 경계 부근에서 흔들리는 것을 막을 수 있다. 다음으로 쿨다운·디바운스를 둬서, 시작은 움직임이 일정 프레임 이상 지속돼야 인정하고(순간 노이즈 무시) 종료는 조용한 상태가 일정 시간 이상 이어져야 확정한다. 이렇게 하면 잠깐 멈췄다고 해서 하나의 사건이 둘로 쪼개지지 않는다. 여기에 더해, 너무 짧아 의미 없는 구간은 버리고(최소 길이) 서로 가까이 붙은 구간은 하나로 합치며(갭 병합), 시작 지점 앞과 종료 지점 뒤에 각각 몇 초의 여유(프리롤·포스트롤)를 붙여 사건의 도입부와 여파까지 함께 담는다.

### 배경차분으로 이벤트 인식

이 스크립트는 길고 길이가 제각각인 CCTV 영상에서, 실제로 무언가 일어난 구간만 골라내고 그 구간을 모델이 소비할 수 있는 프레임 묶음으로 잘라내는 역할을 한다. 전체 흐름은 다음과 같다.

먼저 입력 영상을 처음부터 끝까지 훑되, 모든 프레임을 보지 않고 초당 3장 정도로만 샘플링하여 배경차분(MOG2) 알고리즘에 통과시킨다. 배경차분은 고정된 카메라의 정적인 배경을 학습한 뒤, 그와 달라진 전경(前景) 픽셀을 잡아낸다. 이때 전경 픽셀이 화면에서 차지하는 비율을 모션 점수로 삼는다. 아무도 없는 빈 교실은 점수가 0에 가깝고, 아이들이 움직이면 점수가 올라간다. 모션 감지는 GPU가 필요 없는 가벼운 CPU 연산이라, 무거운 모델을 돌리기 전에 값싸게 "여기 뭔가 있나"를 판단하는 1차 필터가 된다.

다음으로 이 모션 점수의 시간 흐름을 보고 이벤트의 시작과 끝을 결정한다. 단순히 점수가 임계값을 넘는 순간을 시작으로 삼으면 잡음 때문에 켜졌다 꺼졌다를 반복하므로, 시작 임계값과 종료 임계값을 따로 둔 히스테리시스를 적용한다. 즉 점수가 높은 임계값을 넘으면 이벤트가 시작된 것으로 보고, 낮은 임계값 아래로 내려간 상태가 일정 시간(쿨다운) 이상 지속돼야 비로소 종료로 판정한다. 이렇게 하면 아이가 잠깐 멈췄다고 해서 하나의 사건이 둘로 쪼개지지 않는다. 또한 시작 지점 앞과 종료 지점 뒤에 각각 몇 초씩 여유(프리롤·포스트롤)를 붙여, 사건의 도입부와 여파까지 놓치지 않고 담는다.

이렇게 뽑아낸 구간들은 곧바로 쓰지 않고 한 번 더 정리한다. 서로 가까이 붙은 구간은 하나로 병합하고, 너무 짧아 의미 없는 구간은 버린다(최소 길이 필터). 그 결과 [시작초, 종료초] 형태의 깔끔한 이벤트 목록이 남는다. 핵심은, 이 과정을 거치면 처리 대상이 영상 길이가 아니라 실제 사건의 개수에 비례하게 된다는 점이다. 그래서 1시간짜리든 3시간짜리든, 정적인 시간은 걸러지고 사건 구간만 남으므로 가변 길이 문제가 자연스럽게 해결된다.

마지막으로 각 이벤트 구간에서 균일한 간격으로 16장을 추출하여 event_000/, event_001/ 같은 폴더에 저장한다. 이 16장 묶음이 곧 다음 모델의 입력 단위가 된다. VLM에는 이 16장을 하나의 클립으로 넣어 "무슨 상황인지"를 서술하게 하고, SAM-3에는 같은 구간의 프레임 시퀀스를 순차로 넣어 객체를 추적하게 한다. 즉 값싼 모션 감지가 사건 구간의 경계를 긋고, 그 구간만 무거운 모델이 정밀하게 해석하는 2단 구조다.

​```
python -m pip install opencv-python numpy
# 스크립트 상단 VIDEO_PATH, OUT_DIR 수정 후
python event_clips.py
​```

[결과]

​```
영상 길이: 3600.0s, fps: 30.0
감지된 이벤트: 8개
  event_000:   42.0s ~   58.0s (16.0s) → 16장 저장 → .../event_000
  event_001:  310.0s ~  322.0s (12.0s) → 16장 저장 → .../event_001
  ...
완료. 총 8개 클립, 각 최대 16장.
​```

### 튜닝 포인트 (현장 맞춤)

| 파라미터 | 조정 방향 |
|----------|-----------|
| START_THRESH / END_THRESH | 오탐 많으면 ↑, 이벤트 놓치면 ↓ |
| COOLDOWN_SEC | 한 사건이 자꾸 쪼개지면 ↑ |
| MERGE_GAP_SEC | 가까운 이벤트 합치고 싶으면 ↑ |
| MOTION_FPS | 순간 사건 놓치면 ↑ (비용도 ↑) |
| FRAMES_PER_CLIP | VLM 입력 규격에 맞춤(16) |

- 모션 감지는 CPU 연산이라 GPU 불필요 → 워크샵의 "CPU 샘플링은 Graviton" 단계에 딱 맞습니다.
- 이건 후보 구간을 싸게 잡는 것이고, "진짜 무슨 사건인지"는 추출된 프레임을 SAM-3/VLM에 넣어 판정합니다.
- 조명 변화·그림자에 오탐할 수 있으니, 실제 유치원 영상 몇 개로 임계값을 먼저 튜닝하세요. detectShadows=False를 켜고 끄며 비교해도 좋아요.
